# V0.2 DeepSeek 对话与 Token 配额

## 目标

依赖 V0.1。Java 服务端实现供应商适配，完成流式对话、每用户 Token 配额与管理后台。本版没有工具执行，模型对话不等于 ReAct 已实现。

**当前测试策略：**暂不按用户剩余额度拦截提问，用户零额度也可提问；仍记录实际用量和待核对状态。恢复限额前须重新设计预留与验证。

## 任务

- [ ] 明确 DeepSeek 所选模型的上下文限制、工具调用格式、流式用量、错误和中断语义；记录真实接口联调结果。
- [ ] 定义与供应商解耦的消息、工具调用、流式事件和用量接口；实现 DeepSeek 适配及取消、超时、错误显示。
- [ ] 本版每次提问独立处理，仅在请求处理期间临时保留必要内容；不实现跨提问记忆或用户长期记忆。对话正文与模型输出不写入数据库、持久化文件或日志；V0.4 再实现跨轮短期上下文与用户长期记忆。
- [ ] 创建 Token 账户、请求、调整迁移；每次模型调用原子预留、按真实输入与输出用量幂等结算；未知结果保留预留并待核对。
- [ ] 实现管理员后台权限、用户使用量和剩余量、请求明细、筛选和配额调整审计；不展示对话正文。
- [ ] 实现 CLI 余额查看；配额不足停止模型调用。规划、压缩及工具调用的后续模型请求均必须经过相同额度检查。

## 验收

流式对话、用量与后台权限通过真实及模拟测试；两个账号隔离，同账号跨终端余额一致；并发用量记录、重复结算、未知用量和重启安全处理。若不能可靠估算输入或获取可信用量，保留预留、停止不安全请求并明确提示；不把未验证的供应商能力当作已完成。
