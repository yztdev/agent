# V0.3 自研 ReAct 与内置工具

## 目标与依赖

依赖 V0.2。使用 Java 自行实现模型—工具—观察结果循环，不依赖现成 Agent 框架编排；可使用模型 SDK、HTTP 和基础库。采用模型原生工具调用，不要求暴露或持久化模型内部推理过程。Windows 客户端负责本机工具和权限，Linux 服务端负责模型编排。

## 任务

- [ ] 定义统一工具注册表：工具名称、描述、输入 schema、风险、执行位置、超时和结果；校验参数并拒绝未知工具。
- [ ] 实现循环：发送上下文与工具定义 → 模型返回回复或工具调用 → 客户端校验及审批 → 执行 → 返回结构化结果 → 继续调用模型，直到完成、取消、失败或达到预算。
- [ ] 定义请求、任务、调用唯一标识及协议状态；断线、超时或重复结果不能自动重放有副作用的操作，状态不明时告知用户。
- [ ] 内置工具：工作区列举、读取、搜索、文件暂存与差异预览、命令执行，以及可确认只读的本机诊断；路径边界、敏感文件与符号链接检查。
- [ ] 文件先暂存、用户接受后写入，拒绝则丢弃；写入前检查冲突。命令仅在可可靠证明只读时直接执行，未知或可能改变状态须审批。
- [ ] 控制每任务循环次数、调用次数、输出大小、超时与取消；每次模型调用均按 V0.2 的配额预留结算；单个任务的工具循环上下文仅在内存，任务结束清除；跨提问短期记忆和长期记忆留待 V0.4。
- [ ] CLI 显示进度、审批、结果和失败；工具输出和文件内容视为不可信数据，不能改变权限规则。

## 验收

示例项目完成定位、预览修改、批准写入和验证；拒绝或取消后操作不发生，冲突不覆盖；覆盖越界、超时、未知工具、重复调用、服务断线和多次模型配额结算。工具调用过程不将短期对话、模型推理或结果持久化；V0.3 不声称具备系统级沙箱。
