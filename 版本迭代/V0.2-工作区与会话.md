# V0.2 工作区与会话

## 目标与范围

在 V0.1 登录基础上，实现按用户和文件夹隔离的工作区、会话存储与恢复，以及跨设备显式关联。Windows 是客户端目标平台；服务端部署在 Linux，复用 PostgreSQL 和现有 HTTPS 登录。

本版使用人工或测试消息验证会话存取，**不接入 DeepSeek，不提供 AI 回复，也不执行本机文件操作或命令**。模型与 Token 配额在 V0.3 实现。

## 用户体验

用户在任意 Windows 项目目录输入 `agent`，登录后客户端识别当前目录并显示工作区。目录首次使用时默认创建独立工作区，其他目录不会自动继承其会话或记忆。

| 命令 | 行为 |
| --- | --- |
| `/workspace` | 显示当前目录及工作区；提供工作区列表与显式关联入口 |
| `/sessions` | 分页列出当前工作区的会话 |
| `/new` | 在当前工作区创建新会话 |
| `/resume` | 选择并恢复当前工作区的会话 |
| `/delete` | 选择会话并确认删除 |

命令名称及界面细节可在开发时微调，但不得改变隔离及确认规则。

## 工作区与跨设备规则

- 工作区归属于用户，以服务端持久化 ID 标识；本机设备 ID 和规范化目录绑定到一个工作区，设备 ID 不作为认证凭据。
- 不同目录默认独立；不同设备上的同名目录也不会自动关联。首次运行默认创建独立工作区；若用户希望使用已有工作区，可通过 `/workspace` 选择关联。
- 关联前展示目标工作区、来源设备/目录及将载入历史上下文的提示，明确确认后才修改绑定；取消则保留原绑定。关联不会复制、覆盖或同步任何文件。
- 关联后重新查询当前工作区数据，不将原工作区的会话或记忆自动带入新工作区。绑定变更与冲突应有明确反馈，不能静默覆盖其他目录绑定。
- 恢复会话时显示原设备和工作区信息；历史命令不自动重跑，临时授权不继承。原路径不存在时仍可查看历史，但执行本地操作前需选择并检查当前目录。
- Windows 路径规范化需处理大小写、相对路径、符号链接、不可访问路径和目录改名；设备 ID 丢失时视作新设备，需重新明确关联。

## 数据库与服务端

新增 Flyway 迁移，保留 V0.1 的 `users` 与 `auth_sessions` 数据：

| 表 | 作用 |
| --- | --- |
| `devices` | 用户的客户端设备及设备元数据 |
| `workspaces` | 用户拥有的逻辑工作区 |
| `workspace_bindings` | 用户、设备、规范化目录与工作区的绑定 |
| `conversations` | 所属用户和工作区的会话 |
| `messages` | 按会话有序保存的消息和状态 |
| `workspace_memories` | 工作区级任务摘要等记忆；本版可不生成摘要 |

落实项目文档中的组合外键、唯一约束和索引；用户、设备、工作区和会话归属必须一致。消息序号在会话内唯一，并发写入需保证顺序和重复请求处理。

提供设备登记、工作区创建/查询/绑定以及会话创建/分页列表/读取/恢复/删除接口。每次请求从登录令牌确定用户，并在服务端验证资源归属；客户端提供的 ID 不能作为授权依据。会话或消息不能因伪造工作区 ID 而跨账号或跨工作区访问。

## 删除与数据保留

删除会话前要求用户确认；删除后会话不出现在正常列表，消息不再用于自动上下文。实现时明确会话和消息的逻辑删除、物理清理及备份保留方式，并在交付文档中说明；工作区级摘要不应继续包含已删除会话内容，应删除或重新生成相关摘要。删除不会修改客户端本地文件。

## 验收标准

1. 同一用户在两个不同文件夹使用时，默认得到独立工作区；加载或恢复会话不会带入另一工作区内容。
2. 不同用户无法通过任何会话或工作区接口访问彼此数据；数据库拒绝跨用户的无效关联。
3. 两台设备的同名目录默认独立；用户确认关联后可恢复指定工作区，取消则原绑定不变。
4. 会话可创建、分页列出、恢复并经确认删除；消息有序，删除后不出现在正常列表和自动上下文中。
5. 从已有 V0.1 数据库升级后，原账号和登录功能正常；迁移与自动化测试通过。
6. Windows 客户端可连接 Linux 服务端完成上述流程；历史查看不执行命令，也不继承授权。
7. 本版明确显示尚不支持 AI 提问；测试消息不能被误认为模型回复。
