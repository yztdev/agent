# V0.5 MCP 外部工具接入

## 目标与依赖

依赖 V0.3 自研 ReAct 工具注册和审批，使用 MCP 协议接入外部工具。内置工具与 MCP 工具共用统一调度、参数校验和审批机制；Java 自研 Agent 编排，可使用成熟 MCP 协议 SDK。具体 SDK、协议版本和传输方式在技术设计时固定并联调。

## 开发任务

- [ ] 实现 MCP 客户端连接、初始化、工具发现和调用；管理连接状态、重连及服务端能力，定义版本兼容和不支持时的错误提示。
- [ ] 配置 MCP 服务器名称、地址或启动方式及凭据来源；首版具体支持的传输方式、运行位置和首批服务端在技术设计中明确，不宣称未实现的传输已支持。
- [ ] 将 MCP 工具映射为统一工具定义，保留来源和命名空间；校验输入 schema，处理名称冲突、工具变更和结构化结果。
- [ ] 明确客户端本机 MCP 与服务端远程 MCP 的执行位置和权限边界；不让服务端通过 MCP 自动获得客户端文件访问权限。
- [ ] MCP 工具默认视为有副作用或影响未知，执行前展示来源、参数与已知影响并获得本次批准；无法确定时不能自动放行。
- [ ] 对工具描述、资源和输出视为不可信内容，不允许覆盖用户指令或权限策略；不将 MCP 凭据发送给模型或写入日志。
- [ ] 设置调用超时、结果大小、并发与取消限制；对断线或超时后结果不明的副作用操作不盲目重试。
- [ ] 用可控 MCP 测试服务端覆盖发现、调用、拒绝、错误、断线和恶意输出，并用至少一个实际 MCP 工具完成端到端联调。

## 验收标准

1. 内置工具与 MCP 工具可由自研 ReAct 调用，来源和执行位置可见，参数及结果通过统一边界处理。
2. 未批准的 MCP 操作不执行；取消、异常和状态不明时不自动重放副作用。
3. 工具输出不能绕过权限或修改指令层级；凭据、短期消息与工具结果不写入持久化日志。
4. MCP 连接失败不影响其他可用工具；记录实际测试的协议版本、传输方式和 MCP 服务端。
5. 每次触发模型调用均经过用户 Token 配额检查及结算；MCP 本身不直接计模型 Token。
