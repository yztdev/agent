# V0.4 工作区与记忆

## 目标与范围

在 V0.1 登录、V0.2 模型及配额和 V0.3 ReAct 基础上，为每个用户维护一份长期记忆，该用户的所有工作区共用。当前会话作为短期记忆，仅保存在客户端运行内存中，不存入数据库。

Windows 是客户端目标平台，服务端部署在 Linux，复用 PostgreSQL 和 HTTPS 登录。本版将用户长期记忆和窗口级短期上下文接入已有 DeepSeek 对话及 ReAct 循环，不改变既有工具审批与 Token 配额。

## 记忆规则

### 长期记忆

- 每个用户只维护一份长期记忆，按用户 ID 归属；该用户所有工作区共用，同一账号不同设备也使用同一份记忆。不同用户之间严格隔离。
- 长期记忆存入 PostgreSQL，同一账号登录后即可跨设备使用，无须关联工作区。用户可查看、修改或清空自己的长期记忆。
- 不默认把短期会话中的内容转存为长期记忆；本版通过用户明确添加或修改维护。未来如增加自动提取，须另行设计用户知情和控制方式。
- 用户级长期记忆适用于该用户所有工作区的后续会话，不应保存密码、认证令牌等敏感凭据；删除后不再加载，备份清理策略需单独说明。

### 短期记忆与会话

- 短期记忆覆盖从开始当前会话到会话结束的整个过程，包含会话内的多轮用户消息、模型回复和必要工具结果；每次提问或请求结束不会清空。客户端进程内存是保存位置；服务端可在请求处理期间临时接收必要上下文，但不持久化到数据库、磁盘或日志。
- 用户关闭当前客户端窗口、退出客户端、清空会话或进程结束后，短期会话不再保留；断线但客户端进程仍在时，可在用户重新连接后继续使用内存中的上下文。换设备、进程崩溃或重启无法恢复短期会话。
- 本版不创建持久化会话或消息表，不提供历史会话列表、跨设备历史会话恢复或数据库会话删除。用户可查看当前会话并清空内存消息。
- 清空短期会话不会删除长期记忆；删除长期记忆也不会自动改写当前会话中已存在的内容，除非用户清空当前会话。

## 用户体验

用户在 Windows 项目目录输入 `agent` 并登录，客户端识别当前目录和对应工作区，加载该用户的长期记忆，并创建空的内存会话。

| 命令 | 行为 |
| --- | --- |
| `/workspace` | 查看当前本机工作目录 |
| `/memory` | 查看及管理当前用户唯一的长期记忆 |
| `/clear` | 清空当前会话短期记忆，保留长期记忆 |
| `/status` | 显示当前账号、工作区与连接状态 |

命令细节可在开发时调整，但隔离、保存和清空规则不变。对话和工具执行沿用 V0.2、V0.3 的行为。

## 工作区与设备规则

- 工作区为客户端当前本机目录，用于界定本机操作范围；切换工作区时提示并清空当前短期会话，继续使用同一用户的长期记忆。
- 长期记忆只通过已认证的用户 ID 归属和查询，不记录或依赖设备 ID、目录、工作区绑定。任何设备登录同一账号后都可使用这份长期记忆。
- 本版不需要设备登记或跨设备工作区关联；Windows 客户端仍须处理目录规范化、符号链接和不可访问路径。

## 数据库与服务端

新增 Flyway 迁移，保留 V0.1 的 `users` 和 `auth_sessions` 数据：

| 表 | 作用 |
| --- | --- |
| `user_memories` | 每个用户唯一一份长期记忆；`user_id` 为主键及 `users` 外键，包含内容、版本号、创建与更新时间 |

不创建用于持久化短期会话和消息的 `conversations`、`messages` 表，也不为记忆建立设备或工作区关联。记忆接口提供读取、替换或修改及清空当前用户的唯一记忆；从登录令牌确定用户，不能仅凭客户端提供的 ID 授权。并发更新需采用版本号或等效机制避免覆盖。

长期记忆删除后不再返回或加载；数据库物理删除及备份保留周期需在交付文档说明。操作日志仅记录必要状态与标识，不记录短期消息、记忆正文、密码或令牌。

## 验收标准

1. 每个账号仅有一份长期记忆，同账号各工作区及设备共用，不同账号相互隔离。
2. 同一账号在任何设备登录后即可使用同一份用户级长期记忆，无须设备登记或工作区关联。
3. 当前会话消息不写入数据库、持久化文件或日志；同一会话多轮提问间保留上下文，关闭当前窗口、退出或重启后无法恢复，清空会话不删除长期记忆。
4. 切换工作区先提示并清空当前短期会话，继续使用该用户的长期记忆。
5. 从已有 V0.3 数据库升级后账号、登录及 Token 配额正常；越权、数据库约束和迁移测试通过。
6. Windows 客户端与 Linux 服务端可完成上述联调；多轮对话及工具调用遵守记忆与配额规则。
